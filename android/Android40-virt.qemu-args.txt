# 安卓 4.0 (API 15, ICS) 在本仓库默认机器【vexpress-a15】上的启动参考（路线 2）
# ===========================================================================
# 这是路线 2 的启动方式：用 UTM 的上游 QEMU（含各种 ARM 机器）+ 一个【为 vexpress-a15
# 编译】的 Android 内核，而不是那颗 goldfish 的 kernel-qemu。
# （kernel-qemu 是 goldfish 内核，在 vexpress/virt 上会因找不到 goldfish 外设而失败。）
#
# 默认机器 = vexpress-a15（已定稿）：
#   - Android 4.0 用 Linux 3.0 内核；QEMU 的 ARCH_VIRT 支持在 3.11+ 才进主线，
#     3.0 + -machine virt 需要把 ARCH_VIRT 反向移植（改动大、风险高）。
#   - vexpress-a15 的 vexpress_defconfig 在 Linux 3.0 原生支持，无需反向移植，
#     配合 QEMU 自带的内置 dtb，启动链路最稳。因此本仓库以 vexpress-a15 为默认。
#
# 内核（见 scripts/build-android-virt-kernel.sh）：
#   - zImage：为 ARM32 + vexpress-a15 编译的 Android 内核（含 binder/ashmem 等 Android 补丁）
#   - vexpress-a15 上 QEMU 会自动提供 device tree，无需单独传 -dtb
#   - system.img / userdata.img：来自官方 AVD 包的安卓 4.0 用户空间（可复用）
#
# 重要现实（务必读）：
#   安卓 4.0 的 ramdisk 里 init 是按 goldfish 设备写的，在 vexpress-a15 上
#   需要改 fstab / init.rc 让 system 指向 /dev/mmcblk0、data 指向 /dev/vda（virtio-blk），
#   这是真正 boot 起来前的最后一步适配，不在本仓库自动完成（见文件底部提示）。

# --------------------------- 默认：vexpress-a15 ---------------------------
qemu-system-arm \
  -machine vexpress-a15 \
  -cpu cortex-a15 \
  -m 1024 \
  -kernel zImage \
  -initrd ramdisk.img \
  -drive file=system.img,if=sd,format=raw,id=sys \
  -drive file=userdata.img,if=none,format=raw,id=user \
  -device virtio-blk-device,drive=user \
  -append "console=ttyAMA0 rootwait init=/init androidboot.hardware=vexpress" \
  -device smc91c111,netdev=net0 \
  -netdev user,id=net0,hostfwd=tcp::5555-:5555 \
  -serial stdio

# --------------------------- 备选：QEMU -machine virt ---------------------------

# --------------------------- ramdisk / fstab 适配提示（真 boot 前最后一步） ---------------------------
# 安卓 4.0 的 ramdisk 默认 fstab 指向 goldfish 的 /dev/block/* 设备。在 vexpress-a15 上需：
#   1) 把 /system 的挂载来源改成 /dev/mmcblk0（system.img 作为 sd 卡整盘，无分区表，直接是 ext4）
#   2) 把 /data 的挂载来源改成 /dev/vda（userdata.img 作为 virtio-blk 整盘）
#   3) 去掉 goldfish 专用的 nand/mmc/qemu_trace 等挂载项
#   4) 确认 kernel cmdline 的 androidboot.hardware=vexpress 与 init 里的设备名一致
# 这一步需要重新打包 ramdisk.img（解包→改 fstab/init.rc→mkbootfs→gzip）。
